# REST API для блога на Go

Дипломный проект программы «Go-разработчик с нуля». Простое REST API для блог-платформы, включающее регистрацию пользователей, авторизацию, создание постов, комментарии, логирование и корректную обработку ошибок.

## Функциональность
- Регистрация и авторизация пользователей (JWT)
- Хеширование паролей (bcrypt)
- Создание и просмотр постов
- Добавление комментариев к постам
- **Отложенное логирование** действий через канал и горутину (с задержкой 1-2 сек)
- Хранение данных в JSON-файлах
- Полная Docker-контейнеризация

## Технологический стек
- **Go 1.27.3**
- **JWT**: `github.com/golang-jwt/jwt/v5`
- **Crypto**: `golang.org/x/crypto/bcrypt`
- **Env**: `github.com/joho/godotenv`
- **Docker & Docker Compose**

## Старт Приложения:

**Способ 1: Локальный запуск (Go)**

1. Перейдите в папку проекта
cd blog-api

2. Скачайте зависимости
go mod tidy

3. Запустите сервер
go run cmd/api/main.go

**Способ 2: Запуск через Docker (Рекомендуемый)**

1.Собрать и запустить контейнер
docker-compose up --build

2.Остановить контейнер
docker-compose down

Данные (JSON) и логи сохраняются в папках ./data и ./logs.

## API Эндпоинты ##

GET - /api/health  (Проверка безопасности)
POST - /api/register (Регистрация нового пользователя)
POST - /api/login (Вход и получение jwt токена)
GET -  /api/posts (Получить все посты)
GET -  /api/posts/{id} (Получить пост по ID)
GET -  /api/posts/{id}/comments (Получить комментарии к посту)

**Через авторизацию (Authorization: Bearer <token>)**

POST - /api/posts (Создать новый пост)
POST - /api/posts/{id}/comments (Добавить комментарий к посту)

*Отложенное логирование*: При создании поста или комментария событие отправляется в буферизованный канал. Отдельная горутина читает из канала, делает паузу 1-2 секунды и записывает результат в logs/log.txt. При получении сигнала завершения (Ctrl+C) сервер должен корректно останавить горутину (Graceful Shutdown).
*Безопасность*: Пароли хранятся и используются только через bcrypt. JWT-токены имеют срок 24 часа.
*Хранение:* Данные хранятся в JSON-файлах с использованием sync.RWMutex для безопасной конкурентной записи.
